## Candidate fixes (verified against pinned 1.12.2 source; ranked)
1. **Kit bug, `new ore` (S7, verified):** the generator and worldgen.md line 7 place `WorldGenMinable` at `chunkX * 16 + 8 + nextInt(16)`, but `WorldGenMinable.generate` adds 8 itself (lines 34-37), so veins reach chunk+2 and cascade (55 warnings in S7's log). Vanilla `BiomeDecorator.genStandardOre1` passes the chunk corner. Fix: no +8 for `WorldGenMinable` in the generator and the guide (other features still +8); a fixture that runs the generated ore generator on a new chunk and fails on "loaded a new chunk".
2. **Harness bug, `targetPlayer` (S3, verified):** cannot take damage whose true source is a player (`FakePlayer.canAttackPlayer` returns false; `EntityPlayerMP.attackEntityFrom` checks it). Fix: override `canAttackPlayer` (the S3 model's one-line patch); fixture with a player-thrown projectile hitting a target player.
3. **Client-only calls compile, then fail at run time (S5 `SPacketUpdateTileEntity.getNbtCompound`, S6 `EnumDyeColor.getColorValue`; seen twice):** the runtime hint is right but costs a game run. The api index already marks members `[client-only]`. Fix: the deferred client-only lint at build time: a call in `src/main` or `src/gametest` to a name that is client-only on every owner in the index, outside a `@SideOnly(Side.CLIENT)` / client-subscriber class, is an ERROR naming the member.
4. **`useOnBlock` traps (S4, S5; seen twice; verified in `processRightClickBlock` 462-499):** the result is PASS whenever the hand is empty after the click (empty hand, or your `onBlockActivated` used up the last item); when `onBlockActivated` returns false the held item's `onItemUse` runs, so a held block item is placed against the target. Fix: rewrite the TESTING.md `useOnBlock` sentence with both facts.
5. **Tinting (S5, user-visible defect):** `IBlockColor` only tints model faces with a `tintindex`; `block/cube_all` has none (break particles always use tint 0, which is why they were coloured). The client also has to re-render when the colour arrives (`markBlockRangeForRenderUpdate` in `onDataPacket`/`handleUpdateTag`, client side). No tint fact exists in the docs. Fix: a short "Colour handlers" fact in rendering.md (tintindex, parent `block/leaves` for a tinted cube, item/generated layers tint by layer index, re-render on sync, near-white texture); optionally an asset-lint WARN when a mod registers a block colour handler and none of its block models has a tintindex.
6. **Kept-on effects flicker (S7b, user; verified `EntityRenderer.getNightVisionBrightness`: pulses at <= 200 ticks):** fact in effects-enchantments.md: an effect kept on by a condition is re-applied with > 200 ticks (e.g. 300, refreshed below 220) and removed when the condition ends.
7. **Done criterion vs client (S5, S6, S1):** AGENTS.md step 6 already says "what to look at in runClient", but both models reported client parts as verified. Fix: one clause: anything drawn on the client (textures, tint, models, particles, GUI layout) is reported as untested, with what to look at.
8. **Compile hint for block items (S4, verified by the model rerunning `Get-KitCompileHint`):** `Items.STONEBRICK` suggests `Items.BRICK` (a different item). Fix: when `Items.X` is missing and `Blocks.X` exists, hint `Item.getItemFromBlock(Blocks.X)`.
9. **Harness message for exceptions without a message (S6):** an NPE prints `FAIL ... : null` (HarnessMod line 96 uses `String.valueOf(cause.getMessage())`); `NoSuchMethodError` prints only the descriptor. Fix: prefix the exception's simple class name unless it is the harness's own AssertionError.
10. **Circuit breaker (S3 vs S6):** S3 needed 16 failures before STUCK (phase kept changing); S6 printed STUCK after three *different* recipe errors in one phase (progress, not stuck). Fix: key on test + phase + message's first line, plus STUCK when one test fails 5 checks in a row whatever the phase.
11. **Recipe data (S6, verified: `blockWool` exists nowhere in 1.12.2 source):** the model's claim that the harness cannot resolve ore names is wrong; `ore:blockWool` is not a 1.12.2 ore name, and `minecraft:wool` without `"data"` fails to load ("Missing data"). Fix: recipes.md: items with subtypes need `"data"` (32767 = any); harness ERROR when a mod recipe ingredient matches nothing (catches unknown ore names and typos).
12. **QA tool, Read-Trial:** "most repeated" groups failures by test + phase and shows one message, so S6 showed "x5 getColorValue" for five different failures. Fix: group by message too.
