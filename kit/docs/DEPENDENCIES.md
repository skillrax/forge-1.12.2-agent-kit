# Prerequisites

Required for the current Windows kit: PowerShell5.1+, a modern JDK17+ running Gradle (JAVA_HOME), and a discoverable Java8 JDK compiling legacy mods. The tested host JVM is25; every advertised JDK combination and cold-PC setup have not been verified. First build needs internet for pinned dependencies; no global Gradle installation is needed.

Optional recipient tools: Node22+/npm for MCP (setup installs Node LTS when missing); Git for history; ripgrep for scoped searches. Python is a maintainer convenience, not required by this kit. Setup checks Java by default; -WithMcp additionally verifies Node/npm and installs locked MCP dependencies. With -InstallMissing it can install Node through exact WinGet package OpenJS.NodeJS.LTS. Dependencies and caches are not bundled.

Setup.cmd offers a second Y/N prompt explaining why Node/MCP is recommended: direct status, validation and diagnostics tools for your agent client. Both choices occur before downloads. Y installs only when no compatible Node/npm can be found, after Java verification/settings, then runs npm ci and an MCP module-load check. N does not probe/install Node or run npm. Discovery checks PATH and standard Windows Node locations, so a new installation can be used before restarting the terminal. The Node installer may update Windows PATH; restart your agent client/terminals afterward. Module-load PASS is not app connectivity evidence. Node/npm/dependency failures make setup FAIL with remediation; previously verified Java/settings remain in place. Rerun Setup.ps1 -WithMcp -InstallMissing for repair, or choose N for shell-only setup. Installer and npm logs stay under reports/setup; setup-latest.json records the requested MCP state and dependency log. -SkipDependencies skips npm ci but still requires a working MCP module load.

Pinned build: Minecraft1.12.2/Forge14.23.5.2859/stable39, Gradle9.6.0, ForgeGradle7.0.40, renamer1.1.2, Java8 bytecode. PowerShell7/Linux/macOS and cold machines need independent evidence. Forge2864 has user-reported apple gameplay evidence; the automatic baseline remains2859.

Text is UTF-8; scripts explicitly decode UTF-8 and JSON output uses UTF-8. Source-reading helper needs the mapped archive produced by the pinned environment check; custom Gradle caches are resolved via GRADLE_USER_HOME. No developer path is required. Source archives are downloaded/derived locally and excluded from the ZIP.

Setup discovers working64-bit JDKs using actual java/javac output, including JAVA_HOME, PATH, standard Adoptium/user Gradle locations and locally recorded custom homes. A32-bit JRE/JDK does not satisfy this kit. Valid configured JDK17+ is preserved;25 is preferred when discovering a replacement. Missing prerequisites: Setup.ps1 -InstallMissing runs exact WinGet IDs EclipseAdoptium.Temurin.8.JDK then EclipseAdoptium.Temurin.25.JDK as needed, x64, ADDLOCAL=FeatureMain, with logged installer output. It does not silently replace global PATH/JAR associations. Missing WinGet: install Microsoft App Installer or manually install both JDKs. Nonzero installer/reboot/UAC outcomes stop; repair the stated cause then retry. No repeated automatic installation attempts.

Right-click Setup.cmd, Run as administrator. This launcher requires verified JDK25 and JDK8 even if another modern JDK is available. Before checking/downloading JDKs, its Y/N prompt offers machine JAVA_HOME=JDK25 and system PATH beginning with JDK25/bin then JDK8/bin. Existing unrelated PATH entries retain their order; repeated setup does not duplicate these two entries. An existing current-user JAVA_HOME override is also aligned with25 after Y. The early choice is applied only after both actual JDK homes are verified; no second settings prompt is needed. Installer/UAC prompts may still occur. EOF stops before downloads or settings writes. N writes no persistent environment settings. Previous values are backed up under reports/setup/environment-before-*.json before Y writes; failed writes attempt to restore them. Restart terminals and your agent client after Y. JDK25 is the default java command because it comes first; legacy compilation uses the kit's Java8 toolchain selection.

Setup -GradleJavaHome <path> -Java8Home <path> supports custom locations; successful choices are recorded under reports/setup, excluded from distribution. Direct Setup.ps1 remains process-local by default and supports JDK17+; -PromptMachineEnvironment enables the launcher's administrator/Y-N route. Standard agent commands rediscover JDKs without installation; direct gradlew invocation still uses the caller's JAVA_HOME/PATH. Optional -JavaHomeScope User/Machine writes only persistent JAVA_HOME. A laptop user reports successful missing-JDK installation, JAVA_HOME configuration and basic end-to-end mod creation with alpha4. PATH order and a Node-free clean-machine user trial were not observed; Node was already installed. The early-choice alpha5 route still needs recipient observation. Maintainer tests simulate installer/elevation/registry writes without changing the host's Windows environment.

Repeated MCP setup reuses dependencies only when package/lock hashes and the Node/npm identity match the saved successful installation and module loading still passes. Changed dependencies or failed readiness reinstall with locked npm ci. -RepairMcp -WithMcp forces reinstall; -SkipDependencies remains an explicit module-check-only route. npm stdout/stderr and module errors are retained in separate setup logs. npm has a default 900-second timeout (override -DependencyTimeoutSeconds); timeout stops its process tree without automatically retrying. The selected Node directory is added only to this setup process PATH so npm subprocesses work immediately after installation.

Progress goes to stderr, final JSON to stdout. PowerShell5.1 callers redirecting native stderr with ErrorActionPreference=Stop should capture process streams separately (as the kit agent/MCP do), rather than interpreting progress as a terminating PowerShell error. Both raw Gradle streams are retained in logs. New checks emit bounded elapsed/stage observations every5 seconds; stages are buffered log observations, not a completion percentage. ExecutionPolicy Bypass in the launch commands is process-only; organizational policy may still prevent execution.

WinGet also emits elapsed heartbeat messages every5 seconds. At15 minutes it stops waiting by terminating the WinGet launcher and returns failure without retrying; an elevated MSI may remain active, so check installer state before running setup again. No rollback or automatic cancellation of an elevated installer is claimed.

Setup, MCP launcher and agent runner put their own PowerShell module directory first in the process-local PSModulePath. This avoids loading incompatible modules inherited from a different PowerShell host, which can make Get-FileHash unavailable. Setup uses hashing for the MCP dependency identity before npm installation; an error there makes setup FAIL even after Java settings and Node discovery succeeded. Windows module settings are unchanged. The private beta ZIP initially included this correction only in the MCP launcher and agent; the laptop trial exposed the missing setup correction.
